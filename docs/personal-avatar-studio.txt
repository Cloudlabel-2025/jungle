PERSONAL AVATAR STUDIO — November 24, 2026

Player flow
Open My Profile > Customize avatar. Existing expedition players without a personal avatar are invited to create one. First-part flight identity remains hidden until the existing story reveal. The five team task slots remain internal compatibility keys; appearance no longer claims an exclusive character slot.

Choose Male or Female yourself. The scanner does not classify gender, age, ethnicity or identity. Every player may use every hairstyle, outfit and accessory. Both styles support eight outfits (trail jacket, hoodie, varsity jacket, shirt, suit, kurta, dress and sari), nine hairstyles, four facial-hair choices, four eyewear choices, four accessories, three footwear choices, six color channels and eight face proportions. Illustrated full-body and face previews update immediately. Optional local 3D preview supports pointer dragging and keyboard rotation; the camp uses the same personal appearance settings.

Face capture
Enable Camera requests only video, never audio. Capture & Create processes one frame locally with MediaPipe Face Landmarker. The camera stops after capture, on tab changes, when saving or when leaving the studio. A late permission response cannot start a camera after leaving. A local JPEG/PNG/WebP photo (maximum 8 MB) or manual creation is available as a fallback. Small, incomplete, multiple, tilted or turned faces receive corrective feedback. Very poor lighting is rejected. The scan suggests eight coarse face proportions and skin color. Hair, eyes, gender style and wardrobe remain explicit editable choices. The result is a stylized likeness, not an exact photorealistic reconstruction or a Snapchat/Bitmoji integration.

Storage and access
Only validated avatar settings, a version counter and update timestamp are stored. Photos, raw landmark arrays and embeddings are never submitted by this flow; the save service rejects them and unknown fields. Camera images/canvases and local-photo bitmaps are discarded after processing. Active gamers edit only their own avatar. MC and CC see avatars within their existing roster scope; staff never select a player's personal style through the roster UI. Optimistic version checks prevent stale tabs from overwriting a newer avatar. HP, energy, XP, trophies, task ownership and team membership are unchanged by customization.

Runtime and deployment
npm install / npm run prepare copies the pinned @mediapipe/tasks-vision WASM runtime into public/vendor/face/wasm; those generated assets are ignored by Git. public/models/face_landmarker.task is the official float16 model. Both are served locally; the application does not contact an image-generation service. The vision runtime and model are loaded only for a scan, and Three.js loads only for camp/3D previews. Manual wardrobe use needs neither a camera nor the face model. Production camera access requires HTTPS (localhost is supported). A blocked camera/model/WebGL never prevents manual avatar creation.

3D DRESSING ROOM UPGRADE — November 24, 2026

Rebuilt the default editor around an original sculpted 3D character and a light, warm dressing room. The meshes and interface are original procedural artwork; no Snapchat assets or account integration are used.

The default preview is 3D, with full-body/face zoom, pointer and keyboard rotation, subtle breathing/blinking and reduced-motion support. Added Calm / Soft smile / Big smile expressions, Relaxed / Hands on hips / Say hello stances, Balanced / Slender / Broad builds, and three studio backgrounds. Expressions, poses and builds are saved with the avatar. Studio backgrounds are a preview setting. The camera still does not infer gender or build.

Hair, eyewear, accessories and wardrobe now have 3D thumbnail previews. Profile portraits, navigation and camp use the updated art. Portraits are rendered locally from settings using one shared renderer and a bounded 96-image cache. The main editor keeps one renderer while editing, rather than recreating its WebGL context for every color or slider change. Visible thumbnail images load lazily; the illustration remains the fallback when WebGL is unavailable. Camp models use reduced geometry detail.

Existing recipes receive default personality/build settings without losing face proportions, skin/hair colors or clothes. Nested database defaults also support existing documents. Saving still accepts only bounded avatar settings, preserves gameplay resources and ownership, and protects against stale writes. Selfies and raw face meshes are never uploaded or stored by this flow.
