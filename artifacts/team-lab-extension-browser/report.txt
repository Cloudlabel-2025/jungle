   Running node .vow-sync.mjs pulled the actual saved team source automatically.

   edit then reached the real local README automatically (versions 3/4). Git ignore
   rules excluded connection config, metadata, backups and temporary files.

   packages (24 seconds), ran the actual ledger tests and reported four passes,
   zero failures and process exit 0. The fullscreen terminal retained its output.
7. CC inspected the revised source/output and approved version 4. Approval appeared
   in the player's review feed without reloading.
8. Player browser was closed. A new local source file still synced to the team.
   Reopening showed src/local-check.js and version 5 as not reviewed. CC retained
   the old pinned version 4, saw a newer-version banner, and its stale approval
   button was disabled. Historical approval stayed visible instead of transferring.
9. Runner was stopped; different README replacements were made locally and in the
   browser. On restart, the runner paused and retained both versions in the conflict
   report. Neither side was silently discarded. Explicitly choosing the team copy
   updated the local file and retained the local copy in .vow-sync-backups.
10. Verified README content was restored through local editing. It synced as version 7;
    CC inspected and approved that version. Player saw the final current approval.
11. Player disconnected the local runner through the app. The running client stopped
    with its disconnected-connection message, and its bearer was rejected with HTTP
    401. Source files remained intact. App.jsx still matched the implementation that
    passed the four Node tests. HP=5, energy=3 and trophies=0 remained unchanged.

Use in the product
Open Field workshop / coding studio. Download local sync connection, extract the two
files into a dedicated local project folder, and run node .vow-sync.mjs with Node 22+.
Keep the runner running for automatic local/VS Code syncing. Its 12-hour connection
can be disconnected in the lab; it is limited to the current team's source. MC and
CC open Project reviews in their navigation or the coding studio. Reviews are source-
version decisions and do not directly alter player rewards. Remote Git pushes,
deployment services and shared external databases are separate operations.
